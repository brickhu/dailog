# RULES 红线（跨功能底线）

> **索引**：主文档 `SKILL.md`（附录索引）｜ 被 OV-GATE（RULES-9）及全文引用

RULES-1 **不伪造内容**：网页拉取失败/内容无法提取 → 如实汇报，不凭猜测生成脚本
RULES-2 **脚本必须符合 dailog 标准**：点题结构（面向听众的开场——问候 + 自我介绍 + 品牌句 + 背景 + 引嘉宾，埋钩子不剧透；双方称呼不可变）、核心对谈 10 分钟内、
   SC-STEP-1 选题筛选通过（时刻门（可复述/可转移/非 wiki）+ 逻辑骨架 + 价值维度）、提问保真（原生提问全部保留、含义不歪曲）与
   角度保真（话题角度 = 用户呈现意图，节目建议为锚，draft.md 创作原则·核心思想）；无时刻/骨架断裂/任务型对话 → 拒稿
RULES-3 **脚本确认门**：生成后必须给编辑确认（SC-GATE-2 默认在回复正文展示完整脚本全文 + 优化总结），选项编号收口，
   未确认不进 TTS；配套产物（元数据）在 PUB-GATE-1 发布确认门与封面/试听一并确认，未确认不发布
RULES-4 **发布前必须试听**（TTS-STEP-2 merge 自动 QuickTime）：音色克隆异常/断句错误/情绪标签未生效 → 修好再发
RULES-5 **发布/拒稿是外发动作**：先与编辑确认（标题/封面/拒稿原因，选项编号收口），确认后一次执行；
   **republish 同样是外发动作**——必须先试听 + 编辑确认
RULES-6 **拒稿原因必填且具体**：投稿人可见，邮件也会发送——写清楚为什么（见 REJ）
RULES-7 **密钥/token 不出本地**：.dailog-editor/.env 与 session.json gitignored + chmod 600；汇报不打印 token/key；登录走浏览器授权
RULES-8 **内容核查**：进 TTS（TTS-STEP-1）前必须对照 fact_check_list 核实事实（无法核实 → 删除断言）与
   privacy_redactions（逐条确认已泛化）——未核查不进 TTS、不发布
RULES-9 **呈现通道**：所有面向编辑的展示必须在 agent 回复正文（脚本全文单个 code block、封面 Read 直出），
   **禁止用工具输出承载展示**；子代理 JSON 直接写盘，主会话不打印全文
RULES-10 **统一选号格式**：所有确认门（OV-GATE / SC-GATE-1..2 / TTS-GATE-1 / PUB-GATE-1）的选项一律以
   编号列表呈现、**一项一行**：`[n] : <动作说明>`（如 `[1] : 处理《投稿标题》`、`[2] : ✅ 下一步 → TTS`）；
   概要先展示、菜单随后，散文只能作菜单的补充说明，**禁止用纯散文句代替选号菜单**
RULES-11 **环境确认门（新开对话强制）**：触发 skill 后第一步必须先让编辑确认环境 + 验证授权
   （ENV-GATE，见 SKILL.md「会话初始化」）——**未过门不执行任何功能**（连概览也不展示）；
   环境是会话级状态，新开对话一律重走确认门，不默认、不猜测、不沿用旧对话——防「以为是 dev 实际打到 prod」
