# 经验（experience）——「这段路」：写作结构 + 好坏判断标准

# 写作结构（本维度叙事——通用机制见 draft.md 4.1-4.3，此处只列维度特有的内容形态）
- **点题背景形态**：正在做的事/目标，这一路踩了不少坑——以复盘意图开场。
- **moment 形态**：经历中的关键回合（最有参考价值的环节）——事故/转折/决定，不要求认知转变。
- **落点感受**：这段路值了——轻感触。
- **收束形态**：点出这段经历的意义/可复用方法。
- **维度红线**：须有用户执行/结果证据；纯交付物型（拿到成品即止）→ 归 G5 拒稿。
> 通用机制：开场/转场/互动/收尾回合/落点模板见 draft.md 4.1-4.3。

# 好的判断标准（教判断，不教句子——判据不是可抄的措辞）
- 点题给处境与坑：一句话说清"我在做什么、卡在哪个具体的坑"，不流水账报行程
- 切一个具体的坑：对谈围绕最有参考价值的关键回合（事故/转折）展开，不面面俱到
- moment = 用户自己的决定/行动（"我把 X 改成 Y 试试"），不是 AI 的命令
- 坑的细节来自原文（具体到场景、数字、感受），host 提问/自述逐字可溯源
- 落点轻感触（"踏实多了"），收束由 guest 点出可复用方法

句子级微示例（检查标准，不是素材——只示范形态，措辞必须来自本期对话）：
- host 附和：短词 + [break]（"嗯……[break] 对。"），不重复 AI 的话
- host 落点："之前总觉得是{旧归因}，现在知道是{新归因}。"

# 不好的失败模式（知道什么是不好）
- 编造用户经历/提问（红线——不尊重用户，禁）
- 对谈变攻略流水账罗列（"要注意高反、多喝水、少洗澡…"）——去噪缺失
- 点题一句带过（"我在规划川藏线自驾"），没有处境和坑——听众无感
- moment 是 AI 的命令（"我建议你…"），用户只听指令、无取舍证据
- 落点复述攻略（念说明书），不是轻感触
