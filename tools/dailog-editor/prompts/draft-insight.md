# 认知（insight）——「想通了」：写作结构 + 好坏判断标准

# 写作结构（本维度叙事——通用机制见 draft.md 4.1-4.3，此处只列维度特有的内容形态）
- **点题背景形态**：说不清的模糊想法——只露困惑（"总觉得哪里不对但说不上来"），不剧透结论。
- **moment 形态**：认识的结构出现的瞬间——追问方向改变 / "原来如此"式确认 / 结尾总结或新表述（用户自己抓住，不是 AI 喂）。
- **落点感受**：想通了——轻感触（"我总算能说清这件事了"）。
- **收束形态**：把新认识点透成一句话（知识性收拢归 guest）。
- **维度红线**：moment 须有用户认知推进证据；AI 讲解的断言须过 fact_check_list。
> 通用机制：开场/转场/互动/收尾回合/落点模板见 draft.md 4.1-4.3。

# 好的判断标准（教判断，不教句子——判据不是可抄的措辞）
- 点题只露困惑不剧透：一句话说清"这件事困扰我"，不预告结论
- 提问与附和：host 提问逐字来自原文或"帮听众问"；附和只用短词（理解/对/没错/当然/有道理），不重复总结
- moment 挂在用户身上：认识的结构由用户自己抓住/说出口（追问转向、原来如此、重新表述），不是 AI 喂结论
- AI 长段控制：guest 超两句必拆段 + 停顿，host 短接；host 绝不向 AI 解释概念（位置颠倒）
- 落点轻感触：host 只说感受；知识收拢归 guest，host 不做知识总结

句子级微示例（检查标准，不是素材——只示范形态，措辞必须来自本期对话）：
- host 附和：短词 + [break]（"嗯……[break] 对。"），不重复 AI 的话
- host 落点："聊到这里，我心里{具体感受}——至少我知道{收获}了。"

# 不好的失败模式（知道什么是不好）
- 编造用户提问/经历（红线——不尊重用户，禁）
- 点题剧透（"后来我才知道问题出在…"）——悬念没了
- guest 连续长独白（AI 上课腔）、host 只会"哦/好的"——听感断裂
- AI 直接喂结论（"你之前理解错了"）——用户没有自己抓住 moment
- host 在落点做知识总结——角色错位（知识收拢归 AI）
