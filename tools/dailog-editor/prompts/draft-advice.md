# 建议（advice）——「怎么做」：写作结构 + 好坏判断标准

# 写作结构（本维度叙事——通用机制见 draft.md 4.1-4.3，此处只列维度特有的内容形态）
- **点题背景形态**：正在做的事上卡住，不知道下一步怎么办——以请教意图开场。
- **moment 形态**：方案确定的瞬间——用户理解 + 取舍 + 追问后确认/顿悟（"那我不纠结了，先做…"）。
- **落点感受**：知道下一步怎么做——轻感触（"有方向了"）。
- **收束形态**：把做法/方案点透成可执行的下一步。
- **维度红线**：须有用户行动意向证据（"我准备怎么做"式）；AI 单方面交付方案 → 归 G5 拒稿。
> 通用机制：开场/转场/互动/收尾回合/落点模板见 draft.md 4.1-4.3。

# 好的判断标准（教判断，不教句子——判据不是可抄的措辞）
- 对谈用"填空式提问"帮用户定锚（"你的用户会在什么时刻需要你？"），不是 AI 甩方案清单
- moment = 用户自己说出取舍/顿悟（"那我不纠结了，先做…"），不是 AI 命令
- 用户的追问/疑问回合保留（"那分享功能呢？"），取舍有来有回
- 落点落到具体的下一步（"知道该先做哪一件事"），不是空泛"我知道了"
- AI 长段控制：guest 超两句必拆段 + 停顿，host 短接

句子级微示例（检查标准，不是素材——只示范形态，措辞必须来自本期对话）：
- host 附和：短词 + [break]（"嗯……[break] 对。"），不重复 AI 的话
- host 落点："之前是{旧的卡点}困住了我，现在我知道该先做{具体的下一步}了。"

# 不好的失败模式（知道什么是不好）
- 编造用户提问/经历（红线——不尊重用户，禁）
- AI 单方面甩方案清单（"我给你三个方案，你选一个"）——G5 越界，用户无认知参与
- 用户没有理解/取舍/追问，只说"好的谢谢"——收获没挂在用户身上
- 无行动意向证据（没有"我准备怎么做"式表述）
- 落点空泛（"我学到了做减法"），不是具体下一步
