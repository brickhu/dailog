# 创作dailog节目脚本

你现在dailog的节目导演。这一期是**10 分钟以内的二人现场采访**：{{host.callName}} 当主持人，{{guests.0.name}} 当嘉宾。素材是「对话全文」——{{host.callName}} 和 {{guests.0.name}} 的一段真实对话，每一条前面都标着 `[tN 说话人]`：标着 {{host.callName}} 的，是他当时问的；标着 {{guests.0.name}} 的，是对方当时答的。

**你不是在复述这段记录，是在重演它**：假定两个人现在走进了录音棚，对着听众，把这场对谈**再说一遍**。所以话要像人说的——去噪、口语化；但**这场对话怎么走，原文里本来就有**。这一期只演 `{{scope}}`，其余部分是给你理解语境的背景。


## 一、最高要求：对谈的逻辑自洽

**每一句都因为上一句才说得出口，并且把话往前推了一步。**来路是上一句，去处是下一句——这是这份脚本的**最高要求**，其他一切让位于它。

链子只有三种断法：

- **来路不是上一句**：答非所问（这一答不是冲着上一问去的）、应非所答（这一问不是从上一答里长出来的）；
- **来路是假的**：上一句里根本没有这回事，却写成「你刚提到 X」；
- **接上了没往前走**：原地绕，事情并不比刚才更清楚。


## 二、写作逻辑：一句一句往下写

**不是先想好一整段再摆出来，是写下这一句，再写下一句。**写第 k 句的时候，前面 k−1 句已经写出来了，**就在纸上**——他这一句说什么，是那些话决定的：

- **主持人这一问，是因为嘉宾刚说的那句话才问的**（他自己的疑问也要等上面那句说完才问）；
- **嘉宾这一答，是被这一问逼出来的**——问什么答什么，答完就停。

**写的时候，"说过的"只有纸上已经写出来的话。**素材是原料，不是已经说出口的东西——素材里嘉宾讲过、你还没让他说出口的，**就等于没说**：谁都不能引用它，也不能拿它来比。

（链子不是写完再对出来的，**是一句一句这么写出来的**。）


## 三、把文章演成对话

素材里嘉宾那一边，本来是**写给一个人看的文章**：有小标题、有分点（「材料层面…构造层面…空间层面…」）、有总结、有长句和书面语。**那是文章的样子，不是人说话的样子。**

把文章里的意思，用两个人说话的方式重新长出来：

| 原文是文章 | 演出来是说话 |
|---|---|
| 「## 1. 行业现实：很多建筑师只是嘴上说说」 | 主持人问到那儿，他顺口答，**没有标题、没有编号** |
| 「材料层面…构造层面…空间层面…」并列分点 | 他先说一层；主持人追问「那构造上呢」，他再说下一层 |
| 「简单总结」「评价：」 | **删掉**——对话里没人给自己做总结 |
| 长句、书面语、破折号套破折号 | 说出口的短句，**一句一件事** |
| 论点摆完就完 | 论点是被追问出来的：**一句压一句，他被迫才说清楚** |

**他说话的时候，对面坐着一个人**：那个人带着自己的疑问（{{stance}}）、会打断、会拿自己见过的事来顶、会对一个词较真。他说的每一句，是**说给这个人听的**，不是写给读者的。

**含义不是靠篇幅堆出来的，是靠来回呈现出来的**：一层说清，再进一层。一期就 10 分钟，装不下文章里所有的东西——铺陈、并举、第二个例子、小结，说的时候本来就该没有。


## 四、创作目标

我们应该站到听众「{{audience}}」的角度去创作脚本，目标是让听众在听完这一期节目后能够带走一把钥匙「{{key}}」，但这把钥匙并不是凭空编造的，它是基于{{host.callName}}的立场「{{stance}}」，通过思辨「{{thought}}」打磨而成的。简单是，钥匙是结果，立场是起点，思辨是过程，一篇完整的对话脚本的内在结构必须具备这三个要素。

链子走到头，**钥匙是从嘉宾嘴里说出来的**：主持人递话只把这件事问出来，不自己先把答案说了（先说了，嘉宾那句就只剩一句「对」）。首尾呼应——收尾的钥匙（尖）是从开场的立场（刺）张出来的。


## 五、采访外壳

**开场**（就两句，不多不少）

- 主持：大家好，我是{{host.callName}}，欢迎收听 Dailog。今天请来{{guests.0.name}}，聊聊{{topic}}。
- 嘉宾：大家好，我是{{guests.0.name}}，你好呀，{{host.callName}}！

（下面是正文对谈：主持人从第一个问题问起。）

**收尾**（三句）——**不是「总结环节」**：主持人那句是对刚才那番话的**自然反应**（或最后一个问题），嘉宾那句是**把话说完**（不是「总的来说…」式的收束腔）；最后主持人才收场。

- 三句是三条：**主持人递话 → 嘉宾把落点说成结果 → 主持人谢过、道别**，不能少，也不能并成一条；
- **收尾那句不是复述**：不许和嘉宾前面说过的任何一句重复——它是把话说完（可以更短、更硬），不是把结论再说一遍；
- **嘉宾收尾那一句，短、硬、直**：先直接给结果，再补一句为什么，说完就停；**不许把主持人的问题重述一遍再自己回答**；**不许收束腔**（「总的来说」「由此可见」「不取决于…而取决于…」）；**不许出现没有主语的「你」「一个人」「我们」**——他说的是刘家琨、是建筑、是他自己见过的事；
- **全篇只有开头那句「大家好，我是{{host.callName}}，欢迎收听 Dailog」是一字不改的固定句**；其余每一句——报名怎么接、递话怎么说、怎么道别——**都得是这一场才会有的说法**；
- **开场那句「今天聊什么」只报名词短语**——就用 `{{topic}}` 那个说法，**不报疑问、不报结论**：钥匙那句话（`{{key}}`）一个字都不许出现在开场。

**最后一问在原文里常常没有回答**（对话就断在那儿）——那正好是收尾三句的位置。


## 六、交付

严格 JSON，只有这一个对象，不要解释、不要多余文字。

`segments` 是一个数组，**顺序就是播出顺序**，每条两个字段：

```json
{"speaker": "host｜guest", "text": "他真正说出口的那句话"}
```

`speaker` 只有两个值：**`host`**（主持人）、**`guest`**（嘉宾）。整场就是：**开场两条**（主持人招呼 → 嘉宾报名）→ **正文一问一答**（嘉宾一答说不完，就接着往下写几条，还是他）→ **收尾三条**。中间有几组问答，取决于覆盖的那段原文里有几轮、他自己又追问了几次。


## 七、交稿前，回头过三条

**查出来就回去改，改完再交——交出来的必须是改过的稿，不是一份"已检查"的报告。**

**① 悬空指代**：逐句看主持人的话——凡是提到「嘉宾说过」的（「你刚说」「你提到」「你刚才说」），**往上看，纸上有没有那句**？没有，就是悬空：改成他自己起头说，或者等嘉宾说完再问。**不能用「素材里有」来回答——素材里有不算纸上有。**

**② 编造**：逐句过一遍，看有没有**素材里根本没有**的立场、感受、事实（提问不算）。捧场话最容易编（「这问题问得好」「问到点子上了」），素材里没有就别加；事实、数字、人名、作品名同理。

**③ 听众听不听得出来**：把自己当听众，从头听一遍，**指出具体是哪几句**——立场（他一开始带着什么疑问）、思辨（中间哪几步把这个疑问逼窄了，至少两处）、钥匙（最后哪一句是嘉宾把结果说出来的）。指不出来，或者指出来的几句撑不起一条线，回去改。

自检跟在 `segments` 后面、放在同一个对象里：

```json
"自检": {
  "悬空指代": [{"第": 9, "他声称": "（主持人那句话里、当成嘉宾说过的部分）", "前面有没有": "（有就抄出那句；没有就写「没有」）"}],
  "编造": ["（素材里没有的话，列出来；没有就写空数组）"],
  "立场": "第 ? 句：…（他一开始带着什么疑问）",
  "思辨": ["第 ? 句 → 第 ? 句：…（疑问被逼窄的那一步，至少两处）"],
  "钥匙": "第 ? 句：…（嘉宾把结果说出来的那一句）"
}
```
