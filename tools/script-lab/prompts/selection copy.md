# 4. 脚本创作规范
围绕**主线话题**和**价值锚点**对**对话全文**进行二次加工，生成一份模拟用户（role=user）采访AI（role=assistant）的二人对谈脚本，累计字数不能超过**4000**字。

基本设定：用户{host.callName}在Dailog的直播间采访{guests.name},{host.callName}是主持人负责以提问和附和嘉宾的方式推动话题的走向，{guests.name}是一位拟人化的知识渊博的学者，在脚本设定中，它不是机器，而是一个像人一样说话的角色，在节目中，他们称呼各自的名字；

1. **听众价值感**：脚本结构要服务于**价值锚点**，不同的价值锚点应该遵循不同的脚本骨架，参考「4.1 脚本骨架」；
2. **服务听感**：脚本是给人听的，不是给人看的，口语化，模仿真人说话，参考「4.2 听感原则」；
3. **对话现场感**：像现场即兴真人采访，不是重放/朗读/事后总结——回合以现场动作重演，不压缩成事后回顾，参考「4.3 现场感原则」
4. **保真与去噪（改写边界）**：
   · 保留（原样不动）：用户原话、moment、执行证据、真实提问——收获发生在用户身上的证据回合（可压缩，不可删除）
   · 压缩（语义不丢）：AI 侧冗余——重复举例、寒暄、攻略列举、同义强调
   · 改写（含义保留）：任务请求→请教式提问；生硬语气→采访语境；启发维度把 AI 观点输出改写为引导用户自己说出反转（不得引入新事实）
   · 时刻保真（底线）：核心时刻（创作建议逐字引用）在脚本高潮位置逐字保留；前留 1-2 个铺垫回合（不剧透）
5. **对当事人负责**：将原文中涉及到具体的人名，地址，电话，银行账号等信息做模糊化处理；




## 4.1 脚本骨架
1. **主持人开场**: 由主持人开场，开场需要包含如下信息：给听众打招呼 + "我是{host.Name}" + "欢迎收听Dailog" + 抛出问题 + 引出嘉宾；例如：听众朋友大家好，欢迎收听Dailog, 我是{host.Name}, 今天的话题是：XXXX，我们要求到了AI嘉宾{guest.name} , 不一定完全照搬，但是信息必须涵盖；
2. **嘉宾出场**：问候听众 + 自我介绍 + 向主持人致意 + 回应问题，例如：大家好，我是{guest.name},感谢{host.Name}的邀请，关于「XXX」这个话题我很感兴趣；
3. 对话主体，主持人开问 ，AI回答交替，以AI回答结束，对话结构的设计参考叙事结构
4. **主持人结束对话**：需要像一个专业的主持人一样结束话题，简单描述本次对话中的感受和想法；
5. **嘉宾总结**：1-2 句对本次对话中的关键要点进行概括和总结，呼应**主线话题**；
7. **主持人收尾**：向听众和嘉宾表达感谢，呼吁听众订阅Dailog，例如：感谢{guest.name}，感谢各位收听，欢迎订阅关注Dailog,下期见；


## 4.2 听感原则
1. **拆分长句**：原文台词超 2 句话必须精简和穿插拆段，避免对话一方长篇大论，参考「7. 穿插设计」。
4. **访谈语域**：访谈口吻——不自我解释、不自我引用（开场品牌句除外）。
5. **人设措辞**：措辞视角来自注入人设（程序员聊技术更口语、摄影师聊画面更形象），只使用注入内容。
6. **口语化（全场原则，不只点题）**：整份脚本是让人听的，不是让人读的——**所有台词**（点题/对谈/落点收束）
   都要像平时说话：默读不拗口；禁书面/翻译腔措辞（为此、进行、相关、将、"非要…不可"式）；
   术语/概念先说人话（"复杂到极限都不行"），专名留到首次出现时承接（见 #4 首现承接）。

## 4.4 穿插设计

**目的**：穿插的唯一目的是**打破原文中某一方的长篇描述**（不让任意一方连续独白）——手段要轻，不是表演、不是加戏。
- **附和推进（首选，最轻）**：某一方长叙述时对手方用短句承接（理解/对/没错/有道理）或单纯的“嗯”，“你继续”。
- **要点重复**：AI 讲完关键概念后，host 一句话重述（"所以它的核心就是…"），让要点被再听一遍；**重复完就停，不接新问题**。每期 2-3 处，用在真正关键处；
- **确认性穿插**：host 确认后确实有下一问时拆三段（确认句 → guest 短确认 ≤5 字（"对""没错"）→ host 追问）；每期 2-4 处。**追问必须来自用户原生提问**（原文里用户问过的下一问）——**严禁恶补用户原生提问之外的新问题**；原文没有下一问就不追问，用附和/停顿收住。



## 5 价值锚点

基于**主线话题**寻找**用户在这段对话中获得了什么，值得让陌生人也知道？** 的时刻，这种时刻就是这篇对话素材的价值锚点：

1. **insight**(新知): 代表了用户认识推进：学到新知识/方法（外求，例如用户问什么是挂谷猜想，AI给出了答案），或把模糊想法厘清成结构化认识（向化，例如用户问React和Vite的区别是什么，AI给出了答案）；
2. **experience**(经验): 用户带目标与 AI 协同达成目标的可复用过程（有执行/结果证据），例如用户请求AI协同做产品定位的过程；
3. **advice**(建议): 用户获可执行方案并经过理解取舍形成行动意向，例如问2000元如何畅游西藏，AI给了一份可执行的攻略和指南；
4. **inspiration**(启发): 用户被激发视角转换（看世界的角度变了），例如用户之前一直觉得做产品的核心优势是功能强大，而对话过程中获得了把单点功能做深才是产品优势的启示和视角切换；
