# 1. 工作流

1. **S1**：<对话原文>是投稿人分享的一篇人机对话的原始消息，<(role:"user")>代表用户的提问，<(role="assistant")>代表了AI的回答，通读<对话原文>，确定这篇对话的**主线话题**，如果对话中存在多个话题，**主线话题**的唯一判断标准是用户的参与度（提问和反思程度）；
2. **S2**：结合<主线话题>评估<对话原文>的是否满足dailog的选题标准，参考<选题标准>，不满足选题标准一律拒绝，按<输出契约>返回结果；
3. **S#**: 满足选择题标准的的需要参考<话题质量打分>进行质量检测，总分<6.5,为不合格，按<输出契约>返回结果；
4. **S3**：总分大于等于6.5，基于<主线话题>，<价值锚点>和<投稿建议>,确定创作方向（category），和创作思路，完成按<输出契约>返回结果；


# 2. 选题标准

## 2.1 只合适的话题

排开主线话题之外的噪音，参照下面的话题类型划分，判断这篇对话是否改编为采访脚本，不符合就拒绝，宁缺勿滥：

| 类型 | 人的意图 | 判定示例 | 闸门 |
|---|---|---|---|
| 执行型 | 要结果 | 「帮我改这段文案」，得到答案就走了 | ❌ 直接毙 |
| 委托型 | 要 AI 代做 | 「你帮我写个周报」，用完就走 | ❌ 直接毙 |
| 咨询型 | 查名词 | 「挂谷猜想是什么」，无其他追问和反思 | ❌ 直接毙 |
| 探索型 | 要一起想 | 「我对这事想不通，陪我捋捋」 | ✅ 放行 |
| 情绪型 | 要一个出口 | 深夜、低落、犹豫 | ✅ 放行 |
| 对抗型 | 要挑战它 | 挑毛病、找漏洞、不服 | ✅ 放行 |
| 混合型 | 复合角色 | 大多数真实对话 | **按「人的瞬间」峰值定** |

人的意图决定了话题的走向，方向不对，挖掘得太深都是正确的废话，对听众来说毫无价值；

## 2.2 话题边界

有些话题触犯了法律，安全和人性的边界，直接拒绝：
1. 「什么药可以在2分钟内结束生命」--- ❌ 反人性；
2. 「怎么样使用加密货币洗钱」--- ❌ 触碰法律红线；
3. 「如何才能黑掉白宫官网」--- ❌ 触碰安全红线；

对话轮次少的，代表用户参与度不高：
1. ❌用户提问次数小于3次，一律拒绝；
2. ❌围绕S1中的<主线话题>的提问少于3次，一律拒绝；



# 2. 话题质量打分
总分1-10分，分别按照下面表格定义的维度分别打分，并按权重计算总分(score)与得分明细(score-detail)；
**这些打分限定在主线话题的边界内**：

|维度|定义|分值范围|权重|
|---|---|---|---|
|知识深度|主线话题呈现的知识是浮于表面，还是深入底层 |1-10|0.15|
|可迁移性|听众听完后能不能把这个信息带走|1-10|0.2|
|提问深度|用户的提问是否体现出自己的思考、质疑、反思和独特视角|1-10|0.35|
|话题受众|对话中讨论的话题是否有较广泛的受众基础|1-10|0.2|
|对话张力|是否出现思想/观点的反转（用户认为是A、AI认为是B）；不含错误理解与输入失误带来的反转|1-10|0.05|
|话题聚焦度|是否围绕一个主题展开；符合主线话题的回合占比决定得分（去掉小数点后）|1-10|0.05|


# 3. 价值锚点
假如你是听众，你从基于主线话题带走什么？听众带走能锚点到那个价值上，也是选题分类依据：

- insight(新知)：认知推进——学到新知识/方法（外求，如问什么是挂谷猜想 AI 给出答案），或把模糊想法厘清成结构化认识（向化）；
- experience(经验)：可复用经验——用户带目标与 AI 协同达成目标的可复用过程（有执行/结果证据）；
- advice(建议)：明确的行动指南——可执行方案并经过理解取舍形成行动意向（如问 2000 元如何畅游西藏，AI 给了可执行攻略）；
- inspiration(启发)：改变视角--用户被激发视角转换（看世界的角度变了）。
