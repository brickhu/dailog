# Remember · 长期记忆沉淀

用户说「记下」时执行，把本次讨论的结论沉淀为一条长期记忆。

## 执行步骤

1. **回顾结论**：梳理当前对话（尤其最近几轮）达成的决策/约定/踩坑结论，取**最重要的一条**（
   用户说「记下」通常针对刚讨论完的主题；若有多条可合并成一句）。

2. **总结为一句极度精简的话**：
   - 一句话，中文优先，≤ 60 字左右（可含关键名词，如「投稿 ID = 平台标识+内容ID 的 UUID v5」）
   - 保留可操作信息（决策、规则、坑），不要过程描述
   - 格式：`- [YYYY-MM-DD] 一句话结论`
   - 若 MEMORY.md 已有相同/等价结论（同主题），**更新原条目**而非重复追加

3. **追加到 `MEMORY.md`**（项目根）：
   - 不存在则创建，文件头加一行说明：`# MEMORY — 跨会话长期记忆（由 remember skill 维护）`
   - 按日期倒序或正序追加均可，保持简短；最多保留 ~50 条（超出删最旧）

4. **确保 AGENT.md 关联句存在**（防止切换 Agent 后不读取 MEMORY.md）：
   - 检查 `AGENT.md` 是否已包含「任务开始先读 MEMORY.md」（或等价句）；
   - 没有则在「技术要点速查」章节顶部追加一句：
     `- 任务开始先读 MEMORY.md（如已读取过就略过）——跨会话长期记忆见该文件`
   - 已有则**略过**（不重复添加）

5. **提交**：`git add MEMORY.md AGENT.md && git commit -m "docs: 记下 —— <一句话结论>"`
   （AGENT.md 无改动时只提交 MEMORY.md）

## 注意事项

- 只追加**结论**，不写实现过程；用户明确说「记下」才触发，不要主动代劳
- 若结论涉及代码（如某函数的行为约定），可附文件路径，但保持一句话
- MEMORY.md 是跨 Agent 共享的：语句要让不了解上下文的 Agent 也能读懂
