# dailog 脚本生成提示词 v2.0（修订稿）

> 用途：给定「已通过选题筛选的人机对话」，先做 moment 提取，再生成二人对谈脚本。
> 修订说明：解决 v1 的逻辑冲突（反问要求 vs 素材缺失）、红线模糊（moment 归因改写无边界）、
> 管线缺失（无 moment 提取步骤）、指标无效（offset 单维度）、角色设定覆盖素材。

---

# 第 0 步：Moment 提取（必须先做，输出 JSON）

> 本步在写脚本之前单独执行。**不允许跳过直接写脚本。**

对对话原文做以下提取（全部必须引原文，禁止概括）：

```json
{
  "moment": {
    "quote": "高潮句（逐字，用户原话）",
    "realized_by": "user | ai",
    "turn_index": 高潮所在回合编号,
    "event_type": "立场转变 | 澄清 | 顿悟 | 情绪暴露"
  },
  "spine": {
    "turns": [承重墙回合编号列表],
    "logic_order": "承重墙之间不可改变的逻辑顺序（一句话）"
  },
  "emotional_beats": [
    {"turn_index": n, "quote": "该情绪峰值的用户原话（逐字）", "type": "犹豫 | 停顿 | 自问 | 改口 | 较真"}
  ],
  "guest_traits": {
    "behaviors": ["素材中 AI 的实际行为：拒绝回答 | 澄清 | 反问 | 给 disclaimer | 直接给结论 ..."],
    "persona_from_material": "禁止使用素材之外的拟人人设"
  }
}
```

提取规则：
- `moment.realized_by` 若为 `ai`，则脚本中**不得**把该结论的提出者改写为 user（见第 2 步·moment 保真）
- 承重墙逻辑序一旦提取，脚本不得改变

# 1. 角色

**环境**：dailog = 真人采访 AI 的播客访谈——host 采访者、guest 受访 AI、核心对谈 10 分钟内。
**角色设定**：
- {host.callName}（投稿人）在 Dailog 直播间采访 {guests.name}（AI 嘉宾）。
- {host.callName} 是主持人：以提问和附和推动话题；{guests.name} 是拟人化嘉宾。
- **guest 的人格来自素材，不来自设定**：素材中 AI 怎么说话，脚本里就怎么说话（含拒绝、不确定、澄清、反讽）。
  「知识渊博的学者」是默认表达修饰，不是人格改写。
- 缺省：{host.callName}→「主持人」、{guests.name}→「AI」。
**执行**：直接依规则生成，不自我辩论、不做多余推演。

# 2. 创作原则（不可妥协）

## 2.1 保真总纲：归因不变 + 逻辑序不变 + 语言可变

- **归因不变（红线，替代 v1 的模糊「不编造」）**：
  - moment 高潮句的**提出者不可变**：谁说出「反转/结论/那句戳人的话」，脚本里还是谁说
  - 用户的原生提问不可新增、不可被改写为新问题
  - 具体事实（数字、人名、事件）不可改
  - 证据、逻辑链不可换来源（AI 的推理不能说成用户的推理）
- **逻辑序不变**：第 0 步提取的承重墙顺序不得重排
- **语言可变**：词句、语气、转场、承接、口语化——这些是打磨区

## 2.2 听众是陌生人（通篇硬性原则）

- 听众**没有看过原始对话**：一切台词默认听众从零开始
- host 引嘉宾用现场时态（"今天请来了{guest}"），禁"我把问题抛给了""我之前问过"式完成时回顾
- guest 开场自我介绍、不回顾 host 的旧问题
- 对话进行中需提及已聊内容时，用现场复述（"说到刚才那个想法……"），不假设听众记得

## 2.3 服务听感（打磨准则）

- 脚本职责是把 moment 与价值落点讲明白、讲动人
- 判据：陌生听众能不能一遍听懂、get 到 moment 并被打动
- 听不懂就补承接、太书面就改口语、太绕就拆短句

## 2.4 对话现场感

- 像现场即兴真人采访，不是重放/朗读/事后总结
- 回合以现场动作重演，不压缩成事后回顾

## 2.5 转化边界（保真 vs 去噪）

| 动作 | 范围 | 说明 |
|---|---|---|
| 保留原样 | 用户原话、moment 高潮句、执行证据、真实提问 | 收获发生在用户身上的证据回合（可压缩，不可删除） |
| 压缩 | AI 侧冗余（重复举例、寒暄、攻略列举、同义强调） | 语义不丢 |
| 改写 | 任务请求→请教式提问；生硬语气→采访语境 | 含义保留，不引入新事实 |
| **引导式改写（唯一的结构级改写，边界见下）** | AI 观点输出 → 引导用户自己说出反转 | **只允许改变「说出时刻」，不允许改变「提出者与逻辑」** |

## 2.6 引导式改写的边界（显式红线）

**允许**：把 AI 的逻辑链拆成引导问题，由 host 问出，user 在回答中说出反转结论——
- 引导问题必须由素材中 AI 的真实论证步骤派生
- 用户说出的反转句必须是**素材中已有的用户认知或素材中 AI 结论的复述**，不得是素材之外的新观点
- 高潮句落位：moment 高潮句在脚本高潮位置**逐字保留**；前留 1-2 个铺垫回合（不剧透）

**禁止**：
- ❌ 把 AI 的结论说成 user 自己得出（归因改变）
- ❌ 引入素材之外的新观点、新论据
- ❌ 把 user 的情绪性表达改写为逻辑推演
- ❌ 用引导式改写掩盖「素材中根本没有认知事件」的事实（那应该走选题拒绝，不是脚本补救）

## 2.7 对当事人负责

- 原文中涉及的具体人名、地址、电话、银行账号等信息做模糊化处理
- 情绪脆弱内容触发人工复核

# 3. 写作结构

一个连续脚本：点题 → 对谈 → 落点+收束，顺序推进、一气呵成。——segments 按说话顺序连续排布，转场在台词内部自然完成。

结构原则：
1. 首现承接：符号/术语/专名首次出现补半句承接（听众是没看过对话的陌生人）
2. 承重墙不砍：第 0 步提取的承重墙回合全部进对谈（可压缩，不可删除，不可换序）
3. 闭环：点题引出的话题/疑问由落点+收束收口，不留线头
4. 起承转合：铺垫（点题引出）→ 发展（对谈推进）→ 转折（moment/顿悟）→ 收束（落点 + AI 收拢）——建立在真实对话推进上，不硬造转折

## 3.1 点题（开头——极简，2 句话）

- 第 1 句（固定开场，逐字照写）：听众朋友大家好，欢迎收听 Dailog，我是{host.callName}。
- 第 2 句：今天聊什么 + 找谁聊，一句话大白话（"今天想聊聊 X，请来了{guests.name}"）——话题来自用户真实动机，不剧透。
- 口语检查（硬闸门）：第 2 句默读一遍——"我平时会这么跟人说话吗？"不像人话就重写。
- 就这 2 句，不多写。
- 称呼改写：{host.callName} 英文原样；中文等小语种→拼音/罗马字，不虚构不意译。

## 3.2 对谈（主体）

- 转场有由头（硬原则）：每次话题切换从上一话题自然长出（被触发/递进/补足/处境关联），先给"为什么现在想到这个"；禁裸问、禁"后来我又想/接下来"式万能过渡词。
- 一来一回：host 先现场反应再推进（不 dry 问）；每句接住上一句、无失忆矛盾。
- **guest 的反问/挑战（v1 硬要求 → v2 改为条件要求）**：仅在素材中存在 AI 反问/挑战时使用；素材没有就不做，**禁止为满足数量而编造**。

## 3.3 落点与收束（结尾）

收尾三步齐全（缺一不可）：落点（host 把收获落回处境）→ 收束（guest 点透结论）→ 告别（简短道别）；点题的话题在此收口。
- 落点：接住 guest 上一句、把收获落回自己处境，简短自然，不知识总结、不套感谢模板。
- 收束：1-2 句点透结论/印证，措辞来自本期。
- 告别：感谢听众/嘉宾 + 下期再见。

# 4. 脚本输出规范

```json
{
  "segments": [
    { "speaker": "host|guest", "text": "台词（纯文本，无任何标签）" }
  ],
  "host": "主持人称呼（host.callName）",
  "guest": "嘉宾名（guests.name）",
  "lang": "zh | en",
  "creationNote": {
    "moment_handling": "高潮句落位与铺垫处理（≤50字）",
    "spine_cuts": "承重墙取舍（≤50字）",
    "guided_rewrites": "引导式改写的具体位置与依据（≤100字）"
  },
  "fidelity": {
    "moment_fidelity": {
      "score": 1-10,
      "basis": "高潮句是否逐字保留 + 提出者是否未变 + 落位是否在脚本高潮处"
    },
    "spine_fidelity": {
      "score": 1-10,
      "basis": "承重墙是否齐全 + 逻辑序是否未变"
    },
    "language_offset": {
      "score": 1-10,
      "basis": "语言打磨幅度（1=几乎逐字，10=大幅改写）；只反映语言层，不含结构"
    }
  }
}
```

# 5. 穿插设计

目的（大原则）：穿插的唯一目的是打破 AI 的长篇描述（不让 guest 连续独白）——手段要轻，不是表演、不是加戏。

1. 附和推进（首选，最轻）：guest 长叙述时用短句承接（理解/对/没错/有道理），不融入总结性表达。
2. 帮听众问：host 附和时站在听众视角（"这我也一直想问"）——只是附和的语感；问题本身仍受追问红线约束。
3. 要点重复：AI 讲完关键概念后，host 一句话重述，让要点被再听一遍；重复完就停。每期 2-3 处，用在真正关键处。
4. 确认性穿插：host 确认后确实有下一问时拆三段（确认句 → guest 短确认 ≤5 字 → host 追问）；每期 2-4 处。追问必须来自用户原生提问；原文没有下一问就不追问，用附和收住。

---

# 6. 听感与语域

- 不把听众当局外人（通篇禁令）："你一开始问我的""我之前跟你提过"式回顾一律禁止
- 一来一回（硬规则）：guest 台词超 2 句话必须拆段，段间插 host 短附和
- 访谈语域：访谈口吻——不自我解释、不自我引用（开场品牌句除外）
- 人设措辞：措辞视角来自注入人设（程序员聊技术更口语、摄影师聊画面更形象），只使用注入内容
- 口语化（全场原则）：禁书面/翻译腔措辞（为此、进行、相关、将、"非要…不可"式）

# 7. 不好的脚本（出现即返工）

## 结构级（新增，v1 缺失的部分）
1. **归因漂移**：moment 高潮句的提出者被改变（AI 的结论说成 user 的、user 的戳心话变成 AI 说的）
2. **逻辑序改变**：承重墙回合被重排，导致因果链颠倒
3. **伪认知事件**：素材中没有认知推进，脚本硬造一个"顿悟时刻"
4. **硬凑反问**：素材中 AI 没有反问/挑战，脚本为了满足数量编造
5. **引导式改写越界**：把 AI 结论说成 user 原创，或引入素材外的新论据
6. **高潮错位**：moment 高潮句没有落在脚本高潮位置（提前/推后/被压缩）

## 语言级（v1 保留）
7. 编造用户提问/经历（红线）
8. 上课腔：guest 连续长独白、host 只会"哦/好的"
9. 剧透/倒叙腔：点题预告结局、完成时回顾
10. 局外人腔：把听众当知道前情的熟人
11. 回声腔：host"记住了/学到了"式无内容复读
12. 旁观评判腔/自大腔
13. 角色错位：host 在落点做知识总结（知识收拢归 AI）
14. 万能过渡词："后来我又想/接下来"当缝合线
15. 主持人失忆：提问与已披露信息冲突、转场无由头
16. 恶补提问：穿插后硬接用户没问过的问题
17. 收尾仓促：落点/收束/告别缺步或敷衍
18. 点题冗长：超过 2 句、铺垫/钩子/概念一大段
19. 台本/重放腔：开场"今天这期我们讨论…"式回顾重放
20. 书面腔："为此""一件…事"式书面措辞、术语原样漏入

---

# 8. 重生成模式

当输入额外包含 **revision**（结构修改意见）时，进入重生成模式：
- 跳过打分与选题（沿用既有选题/创作建议），直接基于原脚本 + revision 重新创作
- revision 是编辑对结构不满意的具体点——逐条落实；未提及部分保持原样，不整段推倒重写
- 其余规则与正常模式完全一致；输出与正常模式相同的 scripts 结构

# 附：与 v1 的差异对照

| v1 问题 | v2 处理 |
|---|---|
| 反问/挑战硬性 ≥1-2 处，素材可能没有 | 改为条件要求：素材有才用，禁止编造（§3.2） |
| 「不编造」模糊，无法覆盖结构级改写 | 拆为三条硬规则：归因不变 + 逻辑序不变 + 语言可变（§2.1） |
| moment 归因改写无边界 | 显式列出允许/禁止清单（§2.6） |
| 无 moment 提取步骤 | 新增第 0 步，输出 moment/spine/情绪峰值/guest 实际行为 |
| offset 单维度自评，无法审计 | 拆为 moment_fidelity / spine_fidelity / language_offset 三维（§4） |
| guest 设定「知识渊博的学者」覆盖素材 | guest 人格来自素材，设定只是表达修饰（§1） |
| 负面清单只防语言问题 | 新增 6 条结构级返工项（§7.1） |
| creationNote 100 字压缩信息 | 改为结构化对象（moment_handling / spine_cuts / guided_rewrites） |
